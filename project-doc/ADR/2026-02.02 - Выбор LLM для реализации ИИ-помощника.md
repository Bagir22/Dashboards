**Дата:** 24 февраля 2026 г.

**Статус:** Принято

**Контекст:**

В рамках развития функциональности ИИ-помощника нам необходима языковая модель, которая на основе текущих данных дашборда и примененных фильтров будет генерировать краткий текстовый анализ. Модель должна разворачиваться локально для обеспечения конфиденциальности данных, работать на доступных аппаратных ресурсах и демонстрировать приемлемое качество русского языка.

Были определены следующие ключевые требования:
- Бесплатное развертывание: Отсутствие лицензионных отчислений и оплаты за токены.
- Локальная установка: Возможность запуска на собственных серверах Поддержка русского языка: Высокое качество генерации связных аналитических выводов на русском.
- Низкие аппаратные требования: Возможность работы на CPU или с минимальными GPU-ресурсами.
- Достаточный контекст: Способность обработать объем данных с типового дашборда (5–15 графиков) в формате JSON.

**Рассмотренные варианты:**

- Крупные модели (10B+ параметров): GigaChat3-10B, YandexGPT-5-Lite-8B, Qwen2.5-7B. Обеспечивают высокое качество, но требуют GPU с большим объемом памяти (от 16 ГБ VRAM), что существенно увеличивает стоимость инфраструктуры.
- Средние модели (3B–4B параметров): Qwen2.5-3B-Instruct, ruGPT-3.5-3B, Saiga/Mistral-3B. Меньшие требования к ресурсам, могут работать даже на CPU, сохраняя приемлемое качество для задач аналитики.
- Сверхлегкие модели (1B–2B параметров): Qwen2.5-1.5B, Phi-2. Минимальные требования, но качество генерации на русском языке и способность к логическим выводам заметно ниже.

**Решение:**

Выбрана модель Qwen2.5-3B-Instruct (GGUF).

**Обоснование:**

- Достаточное качество для задачи: Модель демонстрирует хорошее понимание инструкций и способность к логическим выводам.
- Низкие аппаратные требования: Модель занимает ~2-3 ГБ оперативной памяти и может работать на CPU. Это позволяет развернуть ее без выделенного GPU-сервера.
- Большой контекст (32K токенов): Модель способна обработать JSON с данными типового дашборда (до 8 000-10 000 записей), оставляя запас на системный промпт и генерацию ответа.
- Мультиязычность: Qwen2.5 хорошо обучена на разных языках, включая русский, что подтверждается тестами и сравнениями с аналогами.

**Последствия:**

- В инфраструктуре проекта появляется новый компонент - сервис инференса LLM.
- Необходимо разработать бэкенд-сервис, который будет:
- Получать текущие данные с дашборда.
- Форматировать их в структурированный JSON (промпт).
- Отправлять запрос в LLM и возвращать ответ на фронтенд.
- Пользовательский интерфейс получит новую кнопку “Сгенерировать вывод” и блок отображения текстового ответа с возможностью копирования.
- Качество генерации будет зависеть от качества промпта; потребуется итеративная настройка prompt engineering для достижения стабильных результатов.
